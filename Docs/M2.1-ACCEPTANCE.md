Baseline: current repository `main`, commit **75118947cf4cf47fafbe455a43d0a574b33105d5**. All baseline files were verified against GitHub blob hashes. Unity project version remains **6000.0.60f1**. This is a surgical update to Build #3, not another milestone.

## Implemented

- Wall placement now samples the current terrain composite from above, validates supported footprint, range, bounds and free space, excludes both Summoners, and snaps the foundation above the surface. Green/red outlined preview and FIRE validation use the same method. Existing Wall construction and destruction are retained.
- The authoritative `Art/WildsDepth1.jpeg` is the independent scenic background. It has no collider and is not modified by terrain destruction. Foreground empty cells render transparently instead of using dark filler. The full original JPEG is displayed on a larger background quad to give the reveal layer different scenic registration. Source pixels, collision profile, map dimensions, camera and spawn locations are unchanged.
- Brighter aiming vector, outlined trajectory dots and outlined placement footprint. Drag math, launch origin, power and partial prediction duration are unchanged.
- Existing opening menu hides combat UI, input surface, movement controls, status/timer and Summoner visuals until PLAY. The existing start/rematch initialization is retained.
- Terrain refresh wakes the existing bodies without repositioning them. AI waits until supported by current collision and vertically settled before deciding. The previous automatic Step escape merely for being lower/unsupported is removed; grounded boundary safety may still use the same finite-charge Step. AI accuracy and other utility scores are unchanged.
- Both Mae presentations use the six production sprites: Idle, A/B/A walking, brief Cast, brief Hit and persistent Defeat. Presentation observes combat/physics and never writes positions or damage. Sprite pivots register the feet to the existing capsule foot; Walk B has separate pixels-per-unit registration for its larger canvas. No sprite rectangle is cropped; no additional frames are generated.
- Six existing Sigil slots use the committed icons while retaining names, uses, ordering and selection. Health and shield values have their supplied frames within the existing HUD area. Existing controls use the primary/secondary skins, slots use normal/selected frames, and the existing menu uses Title.PNG. All text is still Unity text. Decorative Images are non-raycasting children/siblings, so full rectangular touch targets remain intact.
- All 28 PNGs have stable `.meta` GUIDs and explicit single-sprite, source-alpha, uncompressed, full-rectangle imports. A 4096 texture limit preserves their current pixel dimensions. School icons import correctly but have no new selection UI. All runtime references are serialized, not editor-path loads.

## Package and workflow

Upload `AetherWild-M2.1-source.zip` to repository root and `unpack-aetherwild-m2.1.yml` to `.github/workflows/unpack-aetherwild-m2.1.yml`.

This is a small **repository update**, not a standalone project export. The 28 PNGs already committed to main are intentionally omitted from the transport ZIP. The workflow verifies their exact hashes and preserves them, adds their metadata and the updated source, and validates the assembled project before applying anything. All other required project files are at ZIP root, with no nested project directory. Do not delete the existing repository art before uploading.

The workflow preserves `.git`, `.github`, repository production PNGs and unrelated files. It rejects unexpected changes to baseline files before overwriting them. It removes the transport ZIP after successful extraction, commits and pushes main. No direct repository push was made during preparation.
